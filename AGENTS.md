# saorsa-cli

Keyboard-first terminal toolkit. One Ratatui front-end (`crates/saorsa`, tabbed
TUI) backed by reusable headless tools (`sb` Markdown browser/editor, `sdisk`
disk analyser), plus a lean bootstrapper (`cli`, binary `saorsa-cli`) that
downloads, launches, self-updates and runs plugins.

## Layout
- `crates/saorsa` — unified TUI wiring Files, Disk, Git and Plugins tabs.
- `crates/saorsa-cli-core` — shared `Message` bus, `AppCoordinator`, `PluginManager`, history.
- `crates/saorsa-ui` — Ratatui foundation (tab bar, status bar, layout helpers).
- `crates/saorsa-sb`, `saorsa-disk`, `saorsa-git` — tab adapters over `sb`/`sdisk`/git.
- `cli/`, `sb/`, `sdisk/` — standalone binaries.
- `workspace-hack/` is generated by `cargo hakari`; regenerate with `cargo hakari generate`, don't hand-edit.
- `docs/PLUGINS.md` is the authoritative plugin guide; `docs/signing/saorsa-public.asc` is the release key.

## Build and test
- `default-members = ["crates/saorsa"]`, so plain `cargo build` builds only the TUI.
- Run: `cargo run --bin saorsa`, `cargo run --bin saorsa-cli`,
  `cargo run --bin sb -- /path/to/notes`, `cargo run --bin sdisk -- info`
  (non-interactive: `sdisk -- --non-interactive stale --path /tmp`).
- CI (`.github/workflows/ci.yml`): `cargo fmt --all -- --check`,
  `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --all`.
- Release: `./scripts/create-release.sh vX.Y.Z`. The release workflow ships
  `scripts/install.sh` as `saorsa-install.sh` plus GPG `.asc` signatures
  (secrets `GPG_PRIVATE_KEY`, `GPG_PASSPHRASE`). README must show both the
  `curl | bash` path and the GPG-verification path.
- Before shipping, open `saorsa` and click through every tab and run a plugin —
  there is no automated UI coverage.

## Plugins
- Plugins are native `.so/.dylib/.dll` libraries loaded unsandboxed with full
  user privileges. Docs and UI (including the Plugins tab footer) must keep saying so.
- Manifest `saorsa-plugin.toml` sits next to the library; `sha256` (lowercase hex
  of the compiled library) is required — plugins without it are rejected.
  `entry_symbol` defaults to `_plugin_init`.
- Search paths (`crates/saorsa-cli-core/src/plugin.rs`): `~/.saorsa/plugins`,
  `<data dir>/saorsa/plugins`, `/usr/local/share/saorsa/plugins`, `./plugins`.
- First-party `fd` and `rg` wrappers are built-ins (`plugin/builtin_plugins.rs`)
  that shell out to the system binaries.
- The Plugins tab and the bootstrapper plugin menu must stay in parity
  (execute, help/details, directory listing, refresh).

## UI conventions
- Every action needs a reachable keybinding, documented in `README.md` or an in-app overlay.
- Keep draw calls under ~10 ms; background IO goes on a worker thread and reports via the message bus.
- Text editing uses EdTUI 0.11 (vim handler) wrapped by helpers like `sb::editor::MainEditor`; don't roll custom textareas.
- `sb` video support needs `ffmpeg`; keep that documented.
- Config lives at `<platform config dir>/saorsa-cli/config.toml`.
